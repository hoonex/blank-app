# Flow School 모바일 달력 휠 마무리 개선 — 2026-11-25

## 사용자 요청

달력의 월 이동 과정은 유지한다. 회전이 끝난 뒤 날짜 점, 추가 일정 수 `+1`, 행 크기가 한꺼번에 달라지는 후처리 느낌을 줄인다. 회전하는 원의 중심을 화면 아래로 더 멀리 옮겨 반지름을 키우고, 옆 달력과의 간격을 조금 좁힌다. 손가락 드래그·날짜 선택·학교 일정·버스·5탭 등 다른 기능은 유지한다.

## 수정의 원인 및 효과

실제 2027년 1월 정동고 학사일정(26개 날짜에 점, +1 추가 일정 수 6개 표시)을 점검했을 때, 기존 CSS에서는 `+1`의 익명 텍스트 노드가 날짜 버튼 55px 높이 밖으로 **6/6 모두** 넘쳤다. 원본의 날짜 버튼, 점과 익명 `+1` 노드는 수정하지 않고, 표시·줄 높이와 공간만 정렬해 **6/6 모두 날짜 안에 배치**했다.

| 측정 (393px, viewport 높이 850px) | 이전 | 변경 |
|---|---:|---:|
| 회전 반지름(메인 카드 중심 기준) | 약 1,758px | 약 2,225.5px |
| 휠상의 카드 최소 간격 | 12px | 7px |
| 중앙 달력 카드 높이 | 403px | 403px |
| 2027년 1월 추가 일정 수가 날짜 범위 밖으로 넘치는 수 | 6 | 0 |

수정된 CSS는 날짜 셀을 55px에 맞추고, 네이티브 일정 점과 옆 달력의 가상 점을 6px 및 동일한 세로 간격으로 정렬한다. 새 일정 점이 데이터를 받아 채워질 때 `opacity/transform`을 약 300ms로 전환한다. 익명 `+N` 텍스트가 뒤늦게 추가되는 경우 기존 Leptos DOM 노드를 감싸거나 삭제하지 않고, 버튼에 짧은 220ms opacity 애니메이션만 적용한다. `prefers-reduced-motion`에서는 시각 전환을 생략한다. 완전히 알려지지 않은 다음 달 일정은 만들어 내지 않는다.

## 테스트

Chrome headless에서 기존 운영판 자산을 QA 컨텍스트 안에서만 새 파일로 임시 교체한 뒤 비교했다. **실제 삼성 휴대폰 검증은 아님.**

- 가로폭 320/393/590px: 달력 스와이프 왼쪽→다음 달, 오른쪽→이전 달 정상; 월 넘기기 2회→2027년 1월 정상.
- 320/393/590px의 실제 2027년 1월: 달력 날짜 42칸, 각 날짜 버튼 높이 55px, +1 여섯 개가 전부 셀 내부, 화면 가로 넘침 없음, 카드 높이 403px.
- 393px `prefers-reduced-motion:reduce`: 스와이프 및 월 전환 정상, 동일한 카드/추가일정 크기.
- 800/1440px: 모바일 휠 미활성(기존 데스크톱/태블릿 레이아웃 보존), 오늘↔일정 탭 정상.
- 320/393/590px에서 휠 기하 수식 241개 구간 대조: 최소 거리 각각 7.000/7.012/7.016px. 겹침 없음.
- `+1`이 뒤늦게 DOM에 추가되는 테스트: 기존 텍스트 노드를 유지하면서 버튼 자체의 220ms 애니메이션 실행 확인.
- 빈 일정 점에 텍스트가 도착하는 테스트: opacity 0→약 .83–.88(110ms)→1(410ms) 점진 표시 확인.
- 기능 실행 중 uncaught JS 오류 0.
