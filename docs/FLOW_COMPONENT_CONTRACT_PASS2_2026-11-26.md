# Flow School · 공통 컴포넌트 규칙 2차 정리 (2026-11-26)

## 실제 문제와 원칙

사용자는 같은 역할을 하는 카드나 버튼이 페이지마다 서로 다른 모서리, 그림자, hover/press 효과를 쓰는 것이 낮은 완성도의 원인이라고 지적했다. 따라서 **모두 똑같이 생긴 카드**를 강제하지 않고, 역할과 상태를 기준으로 한 디자인 계약을 적용한다.

참고 자료:
- Atlassian Design System 토큰: https://atlassian.design/foundations/tokens/design-tokens
- Atlassian elevation: https://atlassian.design/foundations/elevation
- Carbon Tile 종류와 클릭 동작: https://www.carbondesignsystem.com/building-blocks/core/components/tile/guidelines
- 기존 Flow 문서: `docs/FLOW_SURFACE_SYSTEM_2026-11-26.md`

원칙: 디자인 결정 수치 자체는 Flow의 선택이며, 레퍼런스의 코드나 화면을 복사하지 않는다. 코드 스타일을 새로 덧씌우는 CSS 파일 대신 **기존 활성 파일 안의 실제 선언**을 수정한다.

## 역할별 계약

| 역할 | 예시 | 값·효과 | 이유 |
|---|---|---|---|
| 읽기 전용 표면 | 오늘 급식·캘린더 월간 일정·데스크톱 버스 패널 | `--flow-surface-radius = 24px`; `--flow-surface-shadow`은 밝은 정보 패널에만; 역상 정보에는 그림자 없음 | 같은 정보 계층이 같은 외곽 규칙을 사용 |
| 조작 가능한 타일 | 학교 바로가기, 날짜/버스 선택 | `--flow-action-radius = 14px`; 별도 떠오르는 그림자 없음, hover는 색·경계로만 표현 | 카드 전체가 눌리는 요소와 정보 표면 구분 |
| 세그먼트 컨트롤 | 수업 하루/주간, 급식 주간/월간 | 컨테이너 `--flow-segment-radius = 11px`, 내부 표시 `--flow-segment-thumb-radius = 8px` | 크기가 달라도 같은 컨트롤 종류임을 보이기 |
| 기본 클릭 피드백 | 기본 버튼, 설정, 날짜/주간 셀, 학교 링크 | `--flow-motion-state = 160ms`, `--flow-press-scale = .985`; 임의로 위로 튀는 hover 제거 | 일관된 눌림과 반응 |
| 진짜 떠 있는 메뉴 | 모바일 5탭, 월 선택 다이얼로그 | `--flow-floating-shadow` 등 높은 그림자 | 콘텐츠 위 계층임을 표현 |
| 회전하는 달력 | 이전·현재·다음 월 카드 | `--flow-wheel-shadow`와 기존 회전 모션 유지 | 공간적 캐러셀에 필요한 예외 |
| 맨바닥 정보 | 시간표 타임라인·설정 목록·모바일 버스 검색 | 불필요한 부모 카드 없음 | 모든 항목에 카드를 씌우지 않기 |

**예외:** 플로팅 네비게이션의 드래그/스냅과 달력 휠 모션은 고유 인터랙션이므로 일반 버튼의 160ms 전환을 강제하지 않는다. 다크 모드는 별도 색 토큰을 사용하되 반경과 역할은 유지한다.

## 수정한 실제 선언

1. 기본 `style-f2805f3fda656187.css`: 모바일 `.event-sheet`·`.meal-sheet`·`.bus-panel`의 25px 반경을 표면 토큰에 연결. 설정·기본 버튼, 네비게이션, 주간 셀의 과도한 hover 리프트/눌림을 공통 상태로 변경.
2. `flow-editorial-refine-v2.css`: 급식 22px 및 개별 2px/9px 그림자를 표면 토큰으로 변경; 학교 링크 타일 그림자 제거; 하루/주간과 급식 주간/월간 컨트롤을 공통 반경으로 변경.
3. `flow-meal-single-v2.css`: 활성 단일 급식 표면의 23px을 표면 토큰으로 변경; 동일 클릭 반응을 공유.
4. `flow-motion-polish-v1.css`: 급식 세그먼트/화살표 상태 시간과 클릭 피드백을 공통 토큰으로 변경.
5. `index.html`: 수정한 4개 스타일 시트에 새 버전 쿼리 적용. 기본 CSS의 SHA384 SRI를 **스테이징된 Git blob**으로 다시 계산해 유지.

기존 자료 네트워크, Rust/Wasm, 급식 파서, 학교 선택, 데이터 보안, 버스 BIS 로직, 실제 캘린더 애니메이션은 그대로이다. 별도 사이트인 캠퍼스 지도는 수정하지 않는다.

## 반복 예방 장치

`node scripts/qa-flow-design-system.mjs`는 Node 내장 모듈만으로 디자인 토큰, 표면/액션/세그먼트 반경, 그림자, 눌림 효과, 파일 링크 중복, CSS SRI를 **9개 그룹**으로 검사한다. 일반 CI/스크린샷 QA의 대체물이 아니고, 이 브랜치의 소스에서 실행할 수 있는 회귀 검사다. 앞으로 CSS를 고친 뒤 반드시 실행할 것.

## 검증 및 제한

- 변경 전 운영 계산 스타일: 오늘 급식 **22px**, 월간 일정 상세 **25px**, 학교 바로가기 **14px + 미세 그림자**. 이런 차이는 역할 체계에서 의도된 것이 아니었다.
- 변경 후보의 실제 브라우저 계산 스타일: 급식 **24px + 패시브 그림자**, 월간 일정 상세 **24px + 역상/무그림자**, 학교 바로가기 **14px + 무그림자**; 데스크톱 버스 패널 **24px**, 모바일 버스는 부모 카드 없음.
- Chrome/Playwright, 활성 Leptos/NEIS 경로와 후보 CSS 4개만 교체: 모바일 320·390·590·800px, PC 1366px의 밝은 테마, 390·1366px의 어두운 테마 **7/7 통과**. 페이지 오버플로우와 JS 예외 0건. 탭 복귀, 날짜 선택, 급식 주간→월간 조작 확인.
- 기본 스타일시트의 SRI가 실제로 적용되었는지 `document.styleSheets`/computed custom property까지 확인. 소스 검사가 **잘못 붙은 SRI 마지막 문자**를 발견하여 배포 전에 수정했다.
- **남은 범위:** 온보딩의 모든 입력 상태, 광고 영역, 캘린더 전체 접근성 및 실물 삼성 기기 제스처는 아직 실기기 검증 안 됨. 위 결과를 그 검증까지 포함한 것으로 말하지 않는다.
