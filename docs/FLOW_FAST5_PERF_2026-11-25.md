# Flow School — Fast 5% 검증 보고서 (2026-11-25)

## 결정

전체 Rust 재작성 없음. 프로파일링에서 확인된 **급식 달력 날짜 선택 시 불필요한 DOM 전량 재생성**만 JavaScript로 최적화.

수정 대상: 기존 `flow-meal-refined-v4.js`의 `renderDays()`와 급식 데이터 갱신 시 revision 처리.
운영 파일은 캐시 방지를 위해 `flow-meal-select-fast-v1.js`라는 새 경로로 교체.

## 실제 CPU 프로파일 (기존 운영판)

Chrome DevTools Profiler와 Performance.getMetrics 사용. 393/1440 CSS px, 프로필은 사용자의 별도 브라우저 프로필이 아닌 격리된 테스트 컨텍스트.

| 작업 | 주요 측정 및 발견 |
|---|---|
| 30회 탭 전환, 393px | ScriptDuration 약 234ms; DOM 노드 수 변화 18,119, 별도 레이아웃 작업 다수 |
| 30회 급식 주/월 전환, 393px | ScriptDuration 약 129ms; `renderDays`가 전체 CPU 샘플 약 8.8% |
| 12회 오늘 날짜 선택, 393px | ScriptDuration 약 335ms; Leptos/Wasm 코드도 관측 |
| 유휴 1.2초 | ScriptDuration 거의 0, CPU 샘플 99% 이상 idle |

분석: 가장 직접적으로 제거 가능한 낭비는 같은 달에서 날짜만 바꾸는데 월간 달력(21~23일)의 모든 버튼·요일·스페이서를 다시 생성하는 것.

## 후보 비교와 기각 사유

1. **DOM 캐시 재부착(v5):** 60회 전환에서 생성 노드 수는 3,090→77이지만, 재부착 스타일 계산 증가로 데스크톱 전환 총 시간이 악화. **기각·미배포**.
2. **DocumentFragment 일괄 삽입(v6):** 생성 노드는 3,090→2,910, 일부 시나리오에서 빠르지만 반복 실행 간 일관성이 부족하고 p95 악화 사례 있음. **기각·미배포**.
3. **같은 범위 내 선택만 업데이트(v7):** 실제 날짜 선택에서 반복적으로 개선. **채택**.

## 채택한 변경

`renderDays`는 `모드 + 표시 범위 시작일 + 데이터 revision` 키를 사용:
- 키 동일: 기존 월/주 달력의 버튼은 보존하고 이전·현재 날짜의 `selected`/ `aria-pressed`만 업데이트.
- 키 변경: 기존과 똑같이 모든 날짜를 생성 (다른 주/달, 주간↔월간 전환).
- 새 NEIS API 결과 또는 네이티브 급식 변경: revision 증가, 기존 표시 데이터가 오래되지 않도록 전체 다시 그리기.
- 학교/장면 교체 시 새 UI 호스트가 생성되면 revision 증가.
- 기존 `bindSegment`, `bindSwipe`, Leptos Rust/Wasm, 광고, 시간표, 버스, 내비게이션 코드 변경 없음.

## A/B 속도 측정

Chrome headless, 4× CPU throttling, 48회 월간 **날짜 선택**, 수정 전/후 각 3차례 반복. 매 선택에서 실제 클릭/ARIA 확인 및 DOM 레이아웃 읽기 시행. 실물 갤럭시 벤치마크가 아님.

| 지표 | 기존 | 최적화 |
|---|---:|---:|
| 393px 날짜 선택 중앙값 (3회 범위) | 16.9–21.0ms | 7.3–7.5ms |
| 1440px 날짜 선택 중앙값 (3회 범위) | 14.3–22.4ms | 5.4–8.5ms |
| 48회 동안 JS로 생성된 DOM 요소 | 3,840개 | 144개 |
| 393px ScriptDuration (3회 범위) | 392.9–535.4ms | 202.7–234.6ms |
| 393px LayoutDuration (3회 범위) | 386.9–610.7ms | 97.0–127.2ms |

위 시간은 특정 상호작용의 합/중앙값이며 전체 웹사이트 또는 최초 로딩의 속도 향상을 의미하지 않음. 네트워크 응답은 독립 변수이며, A/B는 사용자 프로필과 실제 학교 데이터 대신 격리된 동일 조건을 최대한 사용했지만 브라우저 실행 노이즈가 존재한다.

## 기능 회귀

운영 페이지에서 실제 JS 파일을 임시 대체해 테스트. 각 320/393/800/1440px에서 16개 항목: 5개 탭 목적지 및 선택 표시, 월간 선택 시 기존 DOM 보존, ARIA pressed 단일 선택, 월간 날짜 수, 월 이동, 주간 5일 복귀, 월간 복귀, 가로 넘침 없음, 5탭 보존, 급식 중복 없음, JS 오류 없음, 후보 실제 사용 확인. **4×16 = 64개 통과**.

1440px에서 Flow 사용 가이드 팝업이 클릭을 가로막는 기존 상황은 정상 닫기 버튼으로 해제 후 재검증했으며 정상 통과.

**늦게 들어오는 NEIS 데이터** 별도 테스트: 현재 달에서 2026년 12월로 넘어갈 때 HTTP API 응답을 인위적으로 늦게 전달하고 임시 모의 식단 `QA속도전용특식`을 넣음. 요청 1건을 가로채 결과가 도착한 뒤 달력 미리보기·ARIA 레이블·상세 음식명에 모두 반영되는지 확인: 통과. 이 모의 식단은 실제 운영 데이터에 저장/전송하지 않음.
